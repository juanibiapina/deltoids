# Review guidance

deltoids can tell you what kind of change each file holds and which
changes need your attention first. TypeSafe's Jev model makes this
judgment for every hunk when the TUI opens.

## Set up

Set `TYPESAFE_API_KEY` in the environment that runs `deltoids`:

```bash
export TYPESAFE_API_KEY=...
```

Without the key, the file list shows no guidance.

<Note>
  With the key set, deltoids sends the changed hunks to TypeSafe. It
  skips package manager lockfiles, which it tags `lockfile` itself, and
  generated files.
</Note>

## Tags and dots

Each file in the file list gets a tag at its right edge and, when it
needs attention, a dot. A file shows the tag and dot of its hunk that
needs the most attention. Each hunk header in the diff shows its own tag
and dot.

| Tag | Change |
| --- | --- |
| `core` | Behavior of the program |
| `refactor` | Structure, with the same behavior |
| `config` | Configuration |
| `deps` | Dependencies |
| `build` | Build files |
| `ci` | CI pipelines |
| `removal` | Removed code |
| `test` | Tests |
| `docs` | Documentation |
| `agents` | Agent instructions, skills, and prompt files |
| `comments` | Code comments only |
| `imports` | Imports only |
| `lockfile` | Package manager lockfiles |

An orange dot marks a change that needs care. A red dot marks a critical
change, including one that breaks code or users outside its package. A
straightforward change gets no dot.

## Hide low-value changes

deltoids mutes the names of tests, comment-only changes, import-only
changes, and lockfiles in the file list.

| Key | Action |
| --- | --- |
| `f` | Hide or show low-value files |
| `F` | Collapse or expand test, comment, and import hunks in the diff |

A collapsed hunk keeps its header, so you still see where it starts.
While a filter is on, a funnel shows at the right of that panel's top
border.
